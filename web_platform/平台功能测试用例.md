# AppUI 自动化测试平台 · 功能测试用例

> 覆盖平台全部功能点。执行方式见文末；`[自动]` 用例由 `web_platform/tests/test_platform_api.py`
> 自动执行（自带平台启停 fixture，端口 8099，不依赖真实设备）；`[手工·需设备]` 用例需连接
> 手机并启动 Appium 后人工或经平台页面执行。

## 一、功能点清单

| 模块 | 功能点 |
| --- | --- |
| P1 首页 `/` | 统计卡（总执行/通过/失败/成功率）、最近执行表（10 条）、清空全部记录、侧边栏、底部设备/Appium 状态灯、8s 自动刷新 |
| P2 执行页 `/run` | conf 下拉切换、设备状态卡、执行参数覆盖（udid/包名/Activity）、用例树（文件勾选联动方法）、全选/全不选、开始执行、执行区（进度条/实时日志/停止/查看详情） |
| P3 执行详情页 `/runs/<id>` | 任务概要、用例执行记录（步骤树/断言截图/错误信息）、执行日志、执行中自动轮询、打开报告、删除本记录、截图 lightbox |
| P4 测试报告页 `/report` | 执行记录分页列表（10/页）、报告生成状态、详情/打开报告/删除、清空全部 |
| P5 代码审查页 `/debug` | 检查项清单（按文件分类）、单项调试、全部验证、结果统计 |
| P6 元素定位器 `/locator` | 302 跳转 127.0.0.1:8001 |
| A1 执行生命周期 | run_id 生成（日期_序号）、单任务互斥、前置校验（Appium→设备在线→App 已安装）、参数覆盖仅本次生效、pytest 子进程、进度统计、日志双通道、30 分钟看门狗、停止（SIGTERM→SIGKILL）、result.json 归档 |
| A2 历史与恢复 | 平台重启后从磁盘 result.json 恢复历史列表/详情/日志、删除单条、清空（运行中保护）、run_id 格式防穿越 |
| A3 报告 | allure generate、报告静态服务（端口探测/就绪等待/同 run 复用/重复清理） |
| A4 安全 | 附件路径防穿越、case_nodes 参数白名单、非法 run_id 拒绝 |
